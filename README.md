# ALTER EGO

Интерактивный Expo-прототип управляемого рабочего присутствия. Сотрудник определяет, что AI-представитель знает, как общается и где вправе отвечать. Возвращается в диалог через перехват и сводку.

## Запуск

Требования: Node.js 20.19+ (для воспроизведения использовался 24.22), npm.

```sh
npm ci
npm run web
```

Expo dev server по умолчанию доступен на `http://localhost:8081`. Для собственного устройства: `npm start`, затем Expo Go, совместимый с SDK 54, либо development build. `npm run ios` и `npm run android` требуют соответствующего локального окружения.

В среде с запретом записи в домашний каталог:

```sh
npm_config_cache=./work/npm-cache npm ci
EXPO_NO_TELEMETRY=1 __UNSAFE_EXPO_HOME_DIRECTORY=./work/expo-home npm run web
```

Никаких API-ключей не требуется. Сборка web: `npm run build:web` (результат `dist/`). Это локальная сборка, не деплой.

## Попробовать сценарий

1. На главной выбрать «Вместо меня».
2. В Identity открыть Persona и изменить тон. В Skills выбрать Lead. В Agency проверить: подтверждение ответов и доступные каналы остались прежними.
3. В «Диалогах» открыть Platform. Выбрать готовую инструкцию либо написать запрос для Alter. AI подготовит локальный черновик с учётом роли и характера.
4. Подтвердить или отклонить черновик. Во время следующей генерации нажать «Перехватить»: запоздалый ответ не появится. Следующее сообщение пишется от человека.
5. В Catch-up выбрать вопрос, перейти к его источнику. Отметить задачу выполненной и сводку прочитанной.
6. Перезагрузить приложение — настройки, история, задачи и режим сохранятся.

## Что работает

- Четыре экрана Expo Router, mobile-first на 390×844 и адаптивный desktop.
- Три режима присутствия; живые статусы и счётчики прочитанного.
- Собственный интерактивный граф: YOU в центре, пять периферийных веток. Relationships необязательна; основной CTA — Agency.
- Настройки тона, подробности, грейда, автономности, памяти и команд. Zustand persist + AsyncStorage; загрузка и ошибки хранения.
- Поиск и фильтры диалогов, человеческие/AI/системные сообщения, AI-черновики, явное подтверждение, смена автора, перехват.
- Контекстные сценарные ответы mock AI, loading, обработка ошибок и UI повторного запроса.
- Защита от публикации старого запроса при перехвате, смене автора, режима или контекста.
- Фильтры сводки, переходы в правильный разговор, выполнение задачи и прочтение сводки.

## Что остаётся mock

Профиль, сотрудники, диалоги, документы памяти и исходная сводка — seed-данные. Mock AI выбирает ответ по теме, запросу, тону, подробности, грейду и включённым источникам; модель не вызывается. Сводка не пересчитывается LLM по новым сообщениям. Сообщения публикуются только в локальную историю. Уведомления, онлайн-статусы и период отсутствия — демонстрационные.

Нет Supabase, авторизации, настоящих корпоративных интеграций, server-side enforcement, push и production-хранения. Срок делегирования, полноценные источники/версионирование знаний, журнал и обращение коллеги к человеку описаны как следующий этап. Проверка обязательств в mock — ограниченная эвристика, а не production-политика безопасности. Персональные настройки пока хранятся на устройстве без шифрования.

## Архитектура

```text
app/                 Expo Router: Presence, Identity, Conversations, Catch-up
src/components/      общие компоненты, adaptive shell, SVG-графика
src/theme/           цвета, типографика, размеры
src/domain/          TypeScript-модели, политики, проверки политик
src/data/            демонстрационные данные
src/store/           Zustand, локальная персистентность, управление диалогом
src/services/        mock AI
PRODUCT.md           идея, JTBD, границы и приоритеты
SPEC.md              маршруты, модели, состояния, acceptance criteria
AGENTS.md            правила разработки и порядок проверки
```

`AIService` и `WorkspaceRepository` в `src/domain/types.ts` — точки расширения для backend-адаптеров. При подключении LLM запрос должен идти через собственный backend; секреты не попадают в приложение. Supabase-реализация потребует auth/RLS и server-side политик. `aiAllowed` не вычисляется из грейда: повышение роли не расширяет доступ.

Детальные результаты ручной и браузерной проверки фиксируются в `VALIDATION.md`. iOS/Android требуют отдельного запуска на устройстве или эмуляторе; web-проверка не заменяет native QA.
